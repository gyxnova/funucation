# learn-by-song

**Tiny lessons, big ideas.** AI/ML concepts taught by a song while simple shapes act out the math on screen. The video pauses, asks you to predict what happens next, then continues. A fresh quiz follows every lesson.

## Why

Students often memorize formulas without seeing the mechanism. In learn-by-song, the diagram *is* the lesson: inputs bounce in, weights light up the wires, the sum builds term by term, and the gate fires or stays dark. The song carries the explanation, and a pause asks "what happens if the bias changes?" before the answer plays.

## What you get

| Lesson | Song | Length |
|---|---|---|
| Perceptrons: weights, bias, z, step and sigmoid, the learning rule | "Zee Above Zero" | 2:47 |
| Activation functions: step, sigmoid, tanh, ReLU, Leaky ReLU, PReLU, ELU, Swish | "Bend the Line" | 2:34 |

- **Predict-then-watch pause** in the middle of each lesson (audio stops exactly there and resumes after you answer).
- **Quiz after every lesson**, different on each play: questions generated live by an LLM from a hand-curated fact sheet, questions generated by code with random numbers (answers computed, never guessed), and curated questions. Each question is labeled with its source.
- **Rewatch this part**: a missed question jumps back to the scene that taught it.
- **Next lesson** when you answer everything correctly.
- Other topics (gradient descent, hashing, feedback control) are listed as "coming soon". They are not built.

## What runs live, and what is produced ahead of time

This is an authoring pipeline plus a runtime player.

| Stage | When | Notes |
|---|---|---|
| Lesson playback and visuals | Live, in the browser | Canvas 2D scenes, each a pure function of time; the same code renders live and for stills |
| Quiz generation | Live | Starts when Play is pressed (about 8 s); falls back to code-generated and curated questions |
| Code-generated questions | Live, instant | Random inputs, answers computed in code |
| Lyrics drafting and review | Before publishing | AI-drafted from the fact sheet, edited by hand |
| Music | Before publishing | Generated with Google Lyria, shipped as an audio file |
| Line timings | Before publishing | Whisper alignment, then manual checks, stored in each topic's JSON |
| Scene templates | Written once | Reused across topics |

Not live: generating a new song for a new topic on demand. An experimental `/api/song` endpoint exists, but on free-tier models it falls back to the curated song, so it is not part of the demo.

## AI components

- **Quiz generation (live).** Open models served through Groq's OpenAI-compatible API, with a fallback model list. The model must return JSON that matches a strict schema. The server then validates it (exactly one correct option, no duplicate options, numbers must come from the fact sheet) and retries with a repair prompt up to two times before falling back. The LLM never invents facts: it only restates and varies the curated fact sheet.
- **Code-generated questions.** Random inputs, weights and bias; every answer is computed in code, and `npm run quizcheck` verifies 500 generated questions (one correct option, distinct options, correct arithmetic).
- **Reviewer pass.** `api/review.py` checks drafted lyrics against the fact sheet (experimental).
- **Music.** Google Lyria (Gemini app) from our lyrics. Line timestamps from Whisper (stable-ts), corrected by hand.
- **Experiments that did not make the final cut.** ACE-Step (open source) on a free Kaggle T4 produced a complete 82-second take, kept as a fallback. Suno's free tier did not allow downloads.
- **Coding assistants.** GitHub Copilot and Claude were used to help write the code. Their output was reviewed and tested; several of their summaries overstated what they had verified, so claims here come from commands we ran and from watching the app.

## Run it locally

Requirements: Node 20+, Python 3.12.

```bash
# API (optional: without it the quiz uses code-generated and curated questions)
python -m venv .venv
.venv\Scripts\activate            # Windows
pip install -r api/requirements.txt
cp .env.example .env              # add GROQ_API_KEY; never commit .env
cd api && uvicorn main:app --port 8000

# Web (second terminal)
cd web && npm install && npm run dev   # http://localhost:5173
```

Checks: `npm run typecheck`, `npm run build`, `npm run quizcheck`, `npm run check:text-overlaps -- perceptron`, `npm run sheet -- perceptron 3` (contact sheet of the whole lesson), and `python -m unittest discover -s api/tests`.

## How a lesson is made

1. Write a fact sheet (`api/data/syllabus/<topic>.json`): facts, numbers, and the scene templates allowed.
2. Draft and review lyrics against the facts.
3. Generate the song; run Whisper for line timings.
4. Put timings, scenes and the quiz pause in `web/public/topics/<topic>.json`. Scene windows come from the lyric lines, so a new song needs only data edits.

## Limitations

- Two lessons exist. Songs are produced ahead of time; there is no on-demand song generation.
- Live quiz generation takes about 8 seconds and depends on free-tier rate limits, hence the prefetch and the fallbacks.
- Timings were checked by ear at key moments, not frame by frame.
- No accounts and no saved progress.
